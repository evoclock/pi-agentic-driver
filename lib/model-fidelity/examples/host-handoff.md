# Agent-host hand-off (v1)

A host can use `host-workflow.v1.json` with the local CLI or opt-in MCP tools. The same `model-fidelity.request.v1` and `model-fidelity.result.v1` apply to both transports. This definition does not execute a workflow, establish reviewer independence, or grant effect authority. On the T15/T14 base, only `prepare`, `diagram`, and `read` run. `check` (#173), `assess` (#168), and `evaluate` (#170) are available only after their draft subcommands merge. Until then, record those steps as not-run and continue other scoped delivery.

The host receives `model-fidelity.to-host.v1` with the actual result ID, bundle ID, finding IDs and published artifact IDs. The host resolves and checks those IDs before acting. The reply `model-fidelity.from-host.v1` repeats the unit, attempt, step, kind, request and bundle IDs. For a recorded step it contains an existing T01 `model-fidelity.caller-step.v1`; validate that record with `validateRecord('caller-step', value)` and the binding with `validateHostHandoff(reply, offer)`. The JSON schema is `../schemas/host-handoff.v1.schema.json`. No host claim is automatically observed evidence. Host-observed provenance must come from the host's actual invocation and artifact readback.

For review, the host stores a review artifact bound to the built bundle and returns its ID. For runtime, it records an actual observation or returns `not-run` and a reason. For rollback, it checks the current revision and manifest digest against the clearance before an effect and records the outcome; `evaluate` runs a second time with a new request ID and the first evaluation cited. For a confirmed red line, the host names the finding and stops only the offending action. A missing review, failed check, unavailable operation, interrupted call or uncertain effect returns `callerStep: null` with a reason. Do not fabricate a successful record or blindly replay the effect. The final `read` uses an actual result or artifact ID and delivery reports the gaps.

The definition is a template, not a literal request file. `$` references are resolved from earlier responses; omit absent review or runtime IDs rather than passing placeholder strings. Each new PAD call uses a unique `requestId`. Changed bytes get a new attempt and bundle. Never overwrite the frozen original plan or prior results. No host repository or live workflow is modified by this example.
