# Poteto mode for Pi sessions

Adapted from Lauren Tan's pstack `poteto-mode` and its **23** playbooks at `cursor/plugins@99743e9c151c8537cbbf1f98bb38f34ef3368453` (MIT). The separate Pi name avoids the unchanged installed upstream skill. Read `../how/WORKFLOW_BOUNDARIES.md` and the matching section in [`playbooks.md`](playbooks.md) before acting. These are methods, not an import of Cursor Task, `poteto-agent`, Custom Modes, `/loop`, its permissive MCP autonomy, its tools or its executable scripts. The existing draft agent-profile line is final as **wording only**; do not claim a live Pi profile loads this skill. Only the repository owner merges.

## Trigger and authority

For an approved non-trivial task in the current Pi session, default to this method **only when it is loaded**. Non-trivial means multiple checkable steps, consequential design, a behavioral boundary or a real failure to diagnose. Skip a casual reply, narrow read-only fact lookup or explicit opt-out; ordinary task safety still applies. A mid-chat new task rematches from its **own** accepted contract. Never claim the mode persists across turns merely because Cursor Custom Mode does; Pi's resource loader and the real bot session must be inspected.

Start from the exact owner scope, intended result, failure case, repo/destination, model/data route, budget, allowed effects and safe exit. Separate an empirical question (a permitted observation/prototype can answer it) from an owner-held product or authority choice. Do not substitute an experiment for a needed grant, or decide an absent owner preference under a broad “autonomy” phrase. Ask the owner only for missing authority or an irreducible consequential call; do permitted read-only investigation yourself. `setup-pstack` configures **exact** `development` and different `independent-review` identities, not defaults. Missing/unavailable roles, capacity, actual worker route or isolation block that delegation. No auto model family, reasoning adjustment, fast slug, provider fallback or guessed data access. A receipt is not a completed worker report.

## Match one playbook and expose the route

Match the task to **one** section of [`playbooks.md`](playbooks.md); write the selected name, why it fits and its steps as session tasks before adding task-specific units when `TaskCreate` is available. Keep a skipped step visible as `skip: <reason>`; do not claim a source step happened when its Pi route is absent. An Investigation is read-only; Bug fix reproduces before fixing; Perf issue measures a baseline while Hillclimb iterates; Runtime forensics captures a live signal while Trace forensics reads an existing artifact. Feature changes behavior, Refactoring preserves a pinned contract, Prototype decides a design, Visual parity needs an immutable image baseline. Skill authoring, blinded Eval, PR status (Babysit), owner-held Shipping and separately gated Opening a PR have different outputs. An Autonomous run has one bounded predicate; Orchestrate is a genuine multi-day program; Autopilot-full/stack are only **proposals** within integration controlled by the repository owner. Session pickup reads an authorized trail; Pause safely needs an actual stop; Multi-phase plan stops before implementation; cleanup audits without deleting. Large one-run or no-fitting-playbook work uses a **loaded** `figure-it-out-pi` to design a bespoke sequence rather than fabricating a playbook. If the selected support section or required Pi method is not loaded, report the missing route and continue only the safe part that does not depend on it.

Throughput checkpoint for a multi-step change: name blocking first steps, independent workstreams, shared writers and smallest safe decomposition; keep an inapplicable dimension with `n/a: <reason>`. Before stateful code, name the data shape and its owner. For a cross-function design use loaded `architect-pi` and any approved design peers; contested choices may use `arena-pi` for same-brief alternatives, `swarm-pi` for independent slices, and `interrogate-pi` for a skeptical exact-artifact review. No route name itself grants a worker. A delegate gets an exact file scope, context pointers, success/failure check, bounded time and forbidden effects; it never runs the parent playbook or rewrites another unit. Read and verify returned artifacts yourself, do not trust summaries, and preserve a different-model reviewer for separate final Standards and Spec contexts. User-path QA is another gate.

## Principle triggers, without name-dropping

The live source has **24** one-rule leaves, each mapped to its own P19–P42 port. Before citing one, verify that its **Pi leaf actually loaded** and read that full leaf in this session; a principle mentioned here is an index, not executable authority. State the concrete choice it changed. If a needed leaf is absent, say its application is `unrun` and use the applicable existing repository safety rule without claiming pstack parity.

- **Scope and structure:** `laziness-protocol`, `subtract-before-you-add`, `minimize-reader-load` for unnecessary layers; `foundational-thinking`, `redesign-from-first-principles`, `model-the-domain` before stateful logic; `outcome-oriented-execution` on planned migrations; `experience-first` and `exhaust-the-design-space` for user-facing forks; `attack-the-premise` after repeated failed shared assumptions; `build-the-lever` only when a rerunnable tool earns its cost.
- **Boundaries:** `boundary-discipline` at outside inputs, `type-system-discipline` at typed API edges, `make-operations-idempotent` for uncertain retries, `migrate-callers-then-delete-legacy-apis` when known callers are inventoried, `separate-before-serializing-shared-state` for competing writers. Types and leases are not runtime containment; unknown external callers cannot be erased by a slogan.
- **Evidence:** `prove-it-works` before declaring completion, `fix-root-causes` after repro, `sequence-verifiable-units` for multi-step work, `test-behavior-not-implementation` for regression tests, `explain-the-number` for measurements. A build or worker report alone is not real-path proof.
- **Delegation and learning:** `guard-the-context-window` for bounded bulk, `never-block-on-the-human` only for already authorized reversible work, `encode-lessons-in-structure` for repeated proven rules. Neither grants private-chat scans or irreversible actions.

## Work and handback

Use the smallest approved unit with a falsifiable check, observe its **actual** entry point, keep failure evidence and iterate within budget. A missing app verifier means the live check is `blocked`, not “green from tests”; offer a project-local creator method only if loaded and separately authorized. Use `show-me-your-work` only through an actually loaded, approved path for long reviewable work; keep the trail private and evidence-linked. No duplicate scheduler, hand-written `TASKS.md`, stock `orch`, PR watcher, worktree cleanup, hidden `bun install` or auto-revert. The Pi `/loop-until-done` draft is only a bounded mechanism if registered and approved; duration alone is not a predicate.

Write a clear reply for the consumer and maintainer: what changed, exact evidence, which checks passed/failed/unran, tradeoffs, open decisions and the next owner action. Never fabricate links or claim a principle was read when it was not. Before a PR or public copy, respect separate approved destination/content review; a source playbook's automatic Opening a PR is **not** inherited. No agent merges, even if an upstream Shipping or Autopilot-full step says to. A pause, hold or loss of effect certainty stops new writes and preserves the trail.

- **Positive BDD:** Given an approved non-trivial Pi task, actually loaded method, selected support playbook, needed Pi leaves and safe real entry, when this mode runs, then it records route and checkable session units, performs only granted effects, proves the result at the real boundary and hands back attributable evidence and owner-held integration.
- **Refusal BDD:** Given a casual/opt-out turn, missing role/leaf/worker capacity/app route, unsafe Git destination, uncertain retry or unapproved merge, when the next source step would require it, then skip the mode or mark that step `blocked`/`unrun` with exact prerequisite; do not fan out, install, open a PR, merge, delete work or claim the Pi session loaded it.

This is an unregistered port draft. Temporary Pi command discovery, text review and source reading do **not** prove Pi default/opt-out behavior or a real positive/refusal journey.
