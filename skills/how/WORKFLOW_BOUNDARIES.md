# Boundaries for the reviewed engineering skills

Read this file whenever using any skill in this seven-skill bundle.

- A skill provides a method, not execution authority. Follow the agreed repository, paths, model/data route, resource bounds, acceptance and stopping point. Escalate missing permission, consequential design changes, ambiguous effects and unresolved acceptance failures; continue ordinary scoped work without repeated approval requests.
- Use asgrep immediately for code lookup; check `pipeline_output/codebase_inventory.jsonl` before new authorship. Read actual source and reuse existing tools. Complexity and duplication are diagnostic signals, not mandatory rejection thresholds.
- Agree BDD-style observable success and failure scenarios first. TDD may help a small deterministic regression; do not impose a new test framework. Scientific results need independent expected values/oracles.
- All new agent workspaces are Treehouse-managed. Provider unavailable means stop workspace creation. A lease is not containment; use the assignment's accepted native or microVM boundary, with no host fallback. Do not create unmanaged worktrees or assume a skill permits a spawn.
- Use existing driver claims and trusted board writer. TaskCreate tracks session work; it does not promote cards or authorize implementation. Do not handwrite TASKS.md, complete canonical cards from worker reports or introduce another scheduler.
- Before any model-role-dependent work, read the project-root `.pi/pstack-model-roles.v1.json` created through `/skill:setup-pstack-pi` (shape: `../setup-pstack-pi/assets/pstack-model-roles.v1.example.json`). Require schema `agentic-driver.pstack-model-roles.v1` and nonempty exact Pi model identities for the needed `development` and `independent-review` roles. If the file or needed role is missing or malformed, report `pstack role <role> is not configured at .pi/pstack-model-roles.v1.json; run /skill:setup-pstack-pi` and stop that workflow. Do not infer a role from a skill, current session or placeholder. A direct read-only method that uses no model role need not be blocked by an unused role.
- For delegated work, use only the configured role and supported installed routing within the model/data grant. Check that a model author actually matches the configured development role and that the resolved reviewer identity matches the configured independent-review role and differs from the author; if identity, availability or grant cannot be checked, stop the independent-review claim and report the gap. No automatic fallback or profile change. A role map is data, not a Pi setting or authorization. Receipts prove submission/delivery, not answers or authority. Make one observation per requested poll; never blindly resend accepted work.
- No agent-invented provider/model defaults, automatic cloud escalation, broad MCP discovery, private-chat scanning or unapproved transcript access. Request access to named files and a limited data range if necessary. No secret values in commands, evidence, logs or commits; approved platform secret stores remain authoritative.
- No destructive shell/interpreter/disk/database/forge actions, reset/force push or automatic disposal. Preserve failed/superseded work through approved archival. Trusted Treehouse return/prune follows verified human merge confirmation; generic sandbox wipe/volume disposal is not implied.
- Scope commits and review-branch delivery to the verified, explicitly approved repository. Only the repository owner merges. Agents never merge a PR, including an independently reviewed PR in an approved private `-agents` or `-dev` repository. A suffix alone grants nothing. Agents must not create public PRs; public pushes require a separately approved exact handoff and outgoing-content review. Release/publication remains owner-held.
- Save sanitized decision/review evidence in an approved version-controlled path. Private corpus/cache representation remains an owner decision. An ignored file is not version-controlled evidence; do not force-add private content or change ignore rules to bypass this. Do not use OS temporary directories.
- Pin reviews to exact base/head or identified dirty artifact; later edits invalidate affected findings. Reports distinguish source inspection, tests actually run, proposed tests, runtime proof and owner acceptance.
- Extend the owner's existing handover with approved evidence pointers and unresolved items. Do not create a competing handover system. Do not run its broad survey/fetch/pruning instructions implicitly.

Aim 2 and Aim 3 remain excluded. GPU/CUDA stacks remain untouched. This bundle does not enable global loading, change settings, install dependencies or authorize live tests.
