# Ralph

Plan in conversation first. Record ordered, independently acceptable items in `fix_plan.md` and its machine-readable companion `fix_plan.json` (`items` with unique `id`, `work` and `accept` argv arrays, `fanout` depth/nodes/concurrency, and a `sections` path). Search the repository before treating an item as missing. Never use placeholders; each acceptance check says why it exists. Keep planning and building separate. The host's work and acceptance commands run sequentially for only the first unfinished item. Only an acceptance exit of zero marks it done. A failed acceptance is a stuck signal, not permission to advance.

Call `python3 scripts/ralph.py --plan fix_plan.json --state ralph-state.json --budget ralph-budget.json` once per iteration. Budget JSON requires positive bounded integers `depth` (≤1), `nodes` (≤1), `concurrency` (≤1), `iterations` (≤100), `wall_seconds` (≤3600). Iterations and fan-out nodes are separate. This runner accepts only declared zero-fan-out commands; it cannot police subprocesses spawned by arbitrary commands. Use only non-fan-out work and acceptance commands. Actual child admission and fan-out budget enforcement belong to a measured outer runner, not this script. A refused declared fan-out does not execute work. After two failures with no decrease in remaining items, gap analysis stops with `gave up`. Never replace a stuck worker merely on its own progress claim. For interactive repeats, use the existing `loop-until-done` bounded route; an unattended runner starts a fresh session per iteration. No second scheduler or handover producer is introduced here.

Each item supplies source-indexed sections in the existing `session-handover` format; the runner calls that producer after each attempted item, even on a closed failure. The next session must consume the previous handover using `python3 scripts/session_handover.py consume handoff/ralph-N.json` before the next iteration. A handover is navigation, not authority. The host checks for the consume marker. An exclusive durable intent is written before work. Treat an uncertain interrupted state as blocked: inspect the intent, handover and work; never replay an ambiguous attempt. If handover creation fails or time expires, the intent remains held and the typed result stops. Recovery requires deliberate external reconciliation, not deleting the intent to retry. Do not use this script for outward effects, automatic commits, pushes, or destructive rollback. Run `make gate` and `make test-gate` on the accepted code path before any commit.

The closed handoff vocabulary is `completed`, `review requested`, `changes requested`, `blocked`, `crashed`, `timed out`, `gave up`. The runner emits `completed`, `changes requested` on a failed check, `blocked`, `crashed`, `timed out`, or `gave up`; `review requested` belongs to the external review seam. Terminal outcomes cannot be retried from the same state. Every result names the item and next action. A `gave up` outcome is a circuit breaker, not a retry instruction. The full fleet runner and typed transport integration are deferred to the outer-runner slice.

Check behavior with `python3 -m unittest tests/test_ralph.py`: one item only, handover before next, no-progress plateau, and refusal without executing work.
