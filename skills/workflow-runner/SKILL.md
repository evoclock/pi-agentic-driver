# PAD workflow runner (draft, voluntary)

For bot-host recipes, this skill describes the **draft CLI and registered Pi facade**. Each workflow is a statechart of pinned `## step: <id>` skill procedures. PAD advances one step at a time after a passing spec gate and checks a new descendant commit plus observed output digest before advance. This is not a guarantee of skill adherence or proof of a fresh installed Pi process. Only run inside an explicitly owner-approved repository/effect scope. The runner's `act` is a non-authorizing intent: dispatch only via the existing guarded Pi worker tools, never raw Herdr shell commands. Do not substitute a worker's `verified:true` for PAD's Git/step checks. The CLI cannot independently attribute Herdr worker answers or authorize an outward effect.

1. Read the exact workflow/skill bytes and the CLI contract described below; detailed design notes live only in the private source checkout. A passing generic lifecycle TLC check is not a check of your task graph. Require that task-specific safe and unsafe configs have the expected results before claiming checked execution.
2. In this draft, `pad-runner run --workflow FILE --run-id ID --event FILE --store DIR` processes one event. Its store is exactly one named child of the repository's `.local/workflow-runner/`; the proposed external `--state-dir` and unified command family are **not yet implemented**. Treat a `duplicate:true` act as the original answer, **not** permission to dispatch a second time. Reconcile unknown dispatches before taking another effect. The CLI accepts one event; Pi tick admits tick/receipt/wake/look/procedure while the Pi gate and dispatch tools handle their own bounded events. Neither surface supplies a trusted absent readback, so an interrupted dispatch cannot obtain a second attempt by replaying it. CLI cancel is unavailable without native owner confirmation; use the Pi cancel tool instead.
3. A receipt must name a new commit after the recorded step base on the expected head. Non-worker steps retain the declared fixed artifact SHA. Spec-backed worker steps freeze the artifact path and record the actual output digest; frozen G8 checks must pass on those exact bytes before advance. The skill must have a `## step: <id>` heading at the frozen Git revision. `procedureDeclared:true` is not `procedureVerified:true`: actual compliance requires a separate trusted step verifier; until present, status is only artifact-checked.
4. A dead-PID writer lock may be retired by the runner's serialized recovery; a live/unknown owner or malformed recovery claim must remain parked for supported reconciliation. A dead recovery claimant with a complete guard record can be retired. Never delete a lock as an agent workaround. Unknown effects must not be resent. A held/cancelled task must not be reset by selecting a new run id.

Pi tools `agentic_workflow_run/_dispatch/_gate/_status/_tick/_cancel` share the draft reducer in the trusted checkout. The guarded dispatch adapter can submit one real worker effect; unknown outcomes park rather than replaying. A prompt or report is not a checked skill receipt. Pi cancel requires native owner confirmation; CLI cancel remains unavailable. Release, Transfer and ReconcileOld are not exposed through these tools, nor is worker/PR attribution. The absent-after-ack readback rule is conformance-only, not proven needed by an outcome TLC control. If a caller requires those effects, report `capability-unavailable`, not a fake completion. Only a reviewed release and fresh installed Pi process establish installed availability.

Worker workflows require a pinned `spec` manifest and a passing G7 host check before act or dispatch. Submit public `spec` through CLI run or Pi `agentic_workflow_gate`; never inject private `_spec` evidence. A chart pin is optional, but when declared its committed bytes must match the human-confirmed digest. The installed checker is resolved through the source registry and must already be available; no tools are installed during a gate. The derived stack, not caller-selected stack data, goes to dispatch. A passing spec gate is required before either act or dispatch.

## G8 completion and gap returns

Submit public `checks` through CLI run or Pi `agentic_workflow_gate` after the receipt. Never inject `_checks`. Effective checks come from the frozen design plus repository defaults; a test per spec invariant and positive observed test counts are mandatory. Failed checks return a structured gap list without spending maxAttempts. Consume the shared producer's handover before redispatch. No-progress, ceiling, zero tests and unknown prior checks effects park rather than loop blindly.

Use `pad-user.v1` to select host, Apple container, Linux or auto. Host runs worker-written code without isolation. Linux uses the guarded native SSH-subsystem route to the backend, never the original proof tool or a raw shell. A scoped standing grant is required for unattended guest checks; attended execution retains the real switch and confirmation. Missing backend/image readiness remains `checks-runner-unavailable`; live-guest acceptance is pending. Keep the authenticated guest route and its readiness checks; never substitute an unguarded shell.

## Limits

A declared procedure and artifact-checked receipt do not establish that a worker executed the skill. The draft runner does not prove general skill-procedure compliance or a live external-bot integration. Keep `procedureVerified:false` without an independent trusted task-bound check; report that gap rather than claiming DONE from a receipt or CLI result.
