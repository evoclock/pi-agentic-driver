# Durable driver run protocol v1

Production import: `@evoclock/pi-agentic-driver/scripts/enforcement/durable_driver_pi.js` (the package includes this path). `openDurableDriver({ directory })` opens a private, canonical, same-owner directory containing a pi-durable 1.0.4 SQLite database. One process owns the directory at a time; `close()` releases it. After a process crash, reopening uses the existing exclusive owner-lock reclamation and the **real** pi-durable `Harness.resume()`; neither a fixture transport nor an opt-in persistence flag is involved. A concurrent owner or ambiguous lock fails closed.

Recovery tests cover process crashes only. The SQLite adapter uses `PRAGMA synchronous = NORMAL`; power-loss and host-crash durability are neither tested nor guaranteed here.

`stepIds` are stable ledger correlation identities, not execution task IDs. Runs written by older versions retain their registration `taskId` values and return those IDs on repeated admission; those tasks do not prove host execution. New runs have no registration tasks. Host execution state and submitted evidence are stored in the run ledger, read through `status()`, and updated through `report()` or `reconcile()`. The consumer type contract is `scripts/enforcement/durable_driver_pi.d.ts`; old run records can lack the per-run `schema` field, while new runs store `agentic-driver.run.v1`.

`schema` and exported `DURABLE_DRIVER_PROTOCOL` are `agentic-driver.run.v1`. Methods:

- `start({runId, steps:[{id,kind}]})`: atomically create a run and ledger correlation ID per step. `kind` is `internal` or `external`. Repeated identical admission returns the same `{runId,digest,stepIds}`; changed identity fails. At most 64 active or held runs are admitted; finished and cancelled history remains addressable and does not consume live capacity.
- `resume(runId)`: return the run and make only its first unfinished step ready. For an external step it first persists `intent` and returns the stable `requestKey`; repeated `resume` by the same open driver returns the live intent without parking it. After reopening with a new owner, `resume` parks an unreceipted intent as `held`. Never infer from a second resume that the external effect should be sent again.
- `status(runId)`: read a snapshot with `state` and ordered `steps` (`id`, `kind`, `correlationId` or legacy `taskId`, `requestKey`, `state`, optional `receipt`). An unknown valid run returns `null`; an invalid ID still rejects.
- `report(runId,{stepId,requestKey,receipt?})`: finish the active internal step after its work is verified, or record a verified external receipt `{requestKey,verified:true,reference}` against the persisted intent. Duplicate identical reports are idempotent. A report is *evidence submitted by the caller*, not proof the effect happened.
- `reconcile(runId,{stepId,requestKey,verified,reference?})`: after host observation of a remote effect, finish an intent/held step only with matching identity and positive evidence; otherwise leave it held. A cancelled run rejects reconciliation without changing its steps; the host must retain independent evidence for an already sent effect. **Never resend on an unknown outcome**. A host must authenticate the observation and validate the exact request identity and remote reference before passing it here.
- `release(runId,{stepId,requestKey,verifiedNotSent:true,reference})`: explicitly reopen a held external intent only after the host independently proves the effect was never sent. Persist the proof reference and replace the request key with a fresh attempt identity; old-key reports are rejected. This is not a recovery path for an unknown outcome. The caller-provided flag/reference is not independent proof or authorization.
- `cancel(runId)`: durably park the run; does not cancel or undo an already issued outward action. The host must reconcile independently before interpreting cancellation as external non-delivery.
- `invokeWorker({requestId,goal,transport,signal})`: persist one external intent for the entire host-owned worker/review/verification invocation before calling the configured transport. The opaque, already-compacted `goal` and stable `requestId` determine the immutable step identity. The transport receives that identity, a driver request key and the abort signal; it must return a host-verified reference and its application-owned result. A changed goal for the same request refuses. A repeated finished invocation returns its step receipt, **not** its result: the host must recover that from its own durable result store. An interrupted intent is held on reopen and is never dispatched again. `reconcile()` accepts a matching independently observed reference; release remains subject to verified non-delivery. This does not checkpoint individual turns or verify effects inside the host.
- `close()`: finish local storage use and release the exclusive lock; refuses while a worker invocation is active.

The driver persists identities, checkpoints and receipts and calls a required application-supplied worker transport; it does not possess a forge credential, independently verify the host's receipt, or grant admission authority. Hosts must verify their destination and effects, keep the returned request key stable, and serialize external execution with the owner lock. They must not treat a caller-provided `verified` bit as authorization or independent proof. This interface never selects a transport on its own; attaching a configured, authorized live transport and reconciling its internal effects are the consuming application's responsibility. Per-turn checkpoints are deferred unless a later crash drill shows they are needed. Cancelled runs refuse further ledger reconciliation.

A process-kill test exercises the installed pi-durable storage: the first process commits an internal completion and an outward intent, dies without closing, and a new process reopens the same directory. The finished step stays finished; the outward intent becomes held until an explicit observation is supplied.
