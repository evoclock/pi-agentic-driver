# Public release

From the source repository (not the public package), use `python3 scripts/release_public.py X.Y.Z --public <public-checkout> --dry-run` for a side-effect-free step list. Prepare a clean source release branch based on `origin/main` and a clean public checkout on `chore/release-X.Y.Z` based on its `origin/main`. Then run without `--dry-run` only when the release version and notes are approved. The command syncs and packs the public branch, refuses archive members that are not tracked source files (including generated Python caches), then pushes the branch and tag, creates a GitHub release, and opens a draft PR. Archive validation happens before the first public push. Review the generated changelog entry and release notes before using them for a real release.

Before the command bumps the version, syncs, tags, or packs, it reads the source `README.md` that sync will copy. If that file contains the status text "merged, unreleased" in any capitalization, the release stops. Features included in this version need released wording in that same README, such as shipped or packaged since X.Y.Z. Do not leave the old label in place and open a later pull request after npm publish only to mark it shipped.

The same check runs in CI for branches named `chore/release-*`. A release pull request cannot pass while the label remains. The shared script is `scripts/check_readme_release_status.py`. Agents Buildkite runs it directly. Public sync copies the script and the public content scan, and the public pipeline already runs that scan, so the public release pull request runs the same check.

Merge the public PR with a **merge commit**. Squash and rebase do not preserve the tagged commit on main. After merging, run `python3 scripts/release_public.py X.Y.Z --public <primary-public-main-checkout> --verify-merged` from the private source repository. This refuses a release worktree or stale main, checks tag ancestry and version, and verifies that every packed file is tracked, generated-file-free, and unchanged from the tag. A dirty file outside the package does not invalidate the package. Only the owner publishes from that verified primary public `main` checkout with their supported npm authentication. Never publish from a release worktree or a downloaded release asset. The command never publishes to npm, merges, or pushes main.
