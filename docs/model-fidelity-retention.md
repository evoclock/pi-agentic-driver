# Model-fidelity retention destination

The retention configuration step returns one JSON object without writing data or contacting a remote. Run `node scripts/model_fidelity_retention.mjs --repo ABSOLUTE_REPO_PATH` for the default `<repo>/.scratch/model-fidelity/`, labelled `local-non-durable`. Add `--destination ABSOLUTE_PRIVATE_STORE_PATH` to select a host-owned private evidence checkout or store. The result is labelled `configured-unverified` until the host independently checks repository identity, visibility, permissions and a successful append-only push. Neither mode publishes or uploads anything. Relative destinations and unknown options exit 2 with JSON error output. Agent workflows can use the same closed-input call before creating a bundle; this step does not alter any existing model-fidelity operation.

To retain a bundle with a JSON manifest, use `node scripts/model_fidelity_retention.mjs --repo ABSOLUTE_REPO_PATH --destination ABSOLUTE_EVIDENCE_CHECKOUT --bundle ABSOLUTE_BUNDLE_DIR --plan-id PLAN_ID --bundle-id BUNDLE_ID`. The destination must be a clean Git checkout of `evoclock/model-fidelity-evidence`. The command checks the exact origin, private visibility and push permission before writing, then copies files into a new `bundles/<planId>/<bundleId>/` directory, copies `manifest.json` last, commits that directory and pushes its current branch. A repeated bundle ID, a link in the bundle, an unverified destination or a non-fast-forward push fails without replacing existing evidence. If a copy, commit or push fails after writing starts, inspect the checkout and remote before any further action. The command does not retry or delete a partial attempt.

The local default remains non-durable. This command does not export cleaned fixtures, change readers or create a database index. A future rebuildable index may use bundle manifests, but it is not a source of truth. No public sync is implied by selecting a path.
