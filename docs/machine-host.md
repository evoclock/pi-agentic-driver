# Local machine commands

The host may construct `createMachineCommands` from `scripts/enforcement/machine_commands_pi.js` with a trusted `boardPath` and host-owned seams. Both `createMachineRest` and `serveMachineMcp` use the same command table; no transport writes the board, run ledger, or reservation database directly. The lane is a view over the board writer, not an alternate write path. A later host integration should call these shared commands.

The standalone entry point is `scripts/machine_host.mjs mcp` (newline-delimited JSON-RPC over stdio) or `scripts/machine_host.mjs rest` (POST `/commands/<name>` on 127.0.0.1 only). Set `PAD_MACHINE_BOARD` to the absolute host `TASKS.md`; optionally set `PAD_MACHINE_ROUTER_DB`, `PAD_MACHINE_RUN_DIR`, and `PAD_MACHINE_PORT`. It does not read filesystem paths or run arbitrary code from a request. REST rejects foreign Host and browser Origin headers. Keep the server private to the current user; loopback is not user authentication.

The standalone server cannot supply native owner confirmation, an authorized claim route, guarded Pi/Herdr transport, or independently verified spawn/missing evidence. Those commands return structured `needs-approval`, `needs-reconciliation`, or `unverified` until a host integrates the corresponding `authorizeCard`, `routeForClaim`, `journey`, `durable.transport`, `verifySpawn`, `verifyMissing`, `verifyReceipt`, and `verifyJourneyFinish` callbacks. A journey with a bound reservation refuses independent finish; the host must settle the claim and reservation together. The completed-reservation finish path needs a verified host settlement integration before it can be exposed. Never implement these callbacks by trusting caller-provided flags, receipts, or authority text. `reservation.verify` is read-back only, never a second spawn. A failed read-back leaves both the claim and reservation held. Settlements require a host verification and an idempotency key; the board audit event commits before reservation release, and an interrupted second half is explicitly `needs-reconciliation` and may be retried with the same key. There is no cross-store atomic transaction: do not describe the pair as crash-atomic.

Only journey, board card, durable run, and live-claim reservation commands are present. Approval, nudge, and other machine surfaces are not exposed. The standalone endpoint does not publish packages or synchronize public state.
