# Verify the bounded Codex boundary

This skill covers scripts/enforcement/attended_authority_guard.js classifyBashCommand, scripts/enforcement/herdr_communication_pi.js executeHerdrPromptExchange, and the reprompt decision in scripts/enforcement/herdr_async_dispatch_pi.js runWorkerJourney. The model sources are docs/state-machines/codex-boundary/guard-model.v1.json and AckHandoff.tla with AckHandoff.cfg. The conformance tests are tests/test_codex_boundary_model.mjs. The mutation runners are scripts/verify_codex_boundary.mjs and scripts/verify_codex_binary_identity.mjs. BinaryIdentity.tla has safe and name-only unsafe configs; guard-model.v1.json lists the binary look-alike cases separately from its shell grammar. The checked code and model sync point is commit fe83724d2fb056556bdc1e36987356077cdf4eb0 (R5-3 release-root follow-up). The synthetic suite, both mutation runners, and safe and name-only unsafe TLC runs were rechecked against that code and model; later changes require a fresh comparison before advancing this record.

## Boundary and limits

The decision table proves only its enumerated command grammar. It does not establish that every possible shell command cannot launch Codex: unseen scripts, aliases, Makefile rules and arbitrary interpreter code are opaque. Never promote the text guard into an account-binding authority claim. The TLA+ model proves only its bounded acknowledgement transitions; replayed fake Herdr traces check whether the actual adapter conforms to them. Actual PID readback and live process behavior remain unverified. Do not run Codex, a live prompt or any account/auth read.

## Re-run in this checkout

Use a temporary isolated Pi profile for the targeted Node suites. Run node --test tests/test_codex_boundary_model.mjs tests/test_codex_spawn.mjs tests/test_herdr_async_dispatch.mjs tests/test_nonpi_pane_comms.mjs tests/test_herdr_communication.mjs tests/test_approval_ledger.mjs. Also run tests/test_attended_authority_guard.mjs when the guard changes. No modeled shell command is executed; strings go only to classifyBashCommand. The mutation runner creates each source copy in os.tmpdir(), first proves an unmutated copy of each source passes, runs model conformance on each mutant copy, and tears it down even if a mutant fails. Run node scripts/verify_codex_boundary.mjs and node scripts/verify_codex_binary_identity.mjs. Also run node --test tests/test_codex_binary_identity.mjs using only os.tmpdir() fixtures. A surviving mutant or missed baseline is a failed verification, not a reason to relax an invariant.

For TLC, copy the reviewed AckHandoff.tla and AckHandoff.cfg into a fresh repo-local .scratch subdirectory and enter that directory. Run this exact direct invocation, using AckHandoff.tla as the spec file:

/opt/homebrew/opt/openjdk/bin/java -XX:+UseParallelGC -cp <OWNER_HOME>/.local/share/tlc/tla2tools.jar tlc2.TLC -workers auto AckHandoff.tla

Do not change global PATH or install Java or TLC. Keep its output in that scratch directory and inspect the completed summary, distinct state count and each invariant from AckHandoff.cfg. For every later run, copy the reviewed source into a new model directory and preserve the earlier output; never overwrite evidence. Follow statechart-pi for interpreting any failed TLC path. Java or jar startup failure is blocked, not a proof; parse, semantic or invariant failures require repairing the model or reporting the counterexample and rerunning.

For the R5-3 model, copy BinaryIdentity.tla and BinaryIdentity.cfg to one fresh temporary model directory and run the same exact Java command above with BinaryIdentity.tla replacing AckHandoff.tla. For the unsafe control, copy BinaryIdentity-unsafe.cfg as BinaryIdentity.cfg to another fresh temporary directory, and repeat that exact invocation. The safe run must pass TypeOK and OnlyAllowedCodexBinary. The name-only control must violate OnlyAllowedCodexBinary, not fail to parse or start. The documented owner-configured path is not read in these synthetic checks. The pass on the bounded models means only the listed failure modes remain distinguishable. When the code changes, update both model and generated traces, test each property against a broken source copy, and record the exact new commit only after comparison and rerun. If behavior outside the bounded grammar can launch a worker, report it as an unverified gap even if these tests pass. Keep failing or superseded observations in the approved evidence area; never alter the fail-first lock or saved gate evidence.
